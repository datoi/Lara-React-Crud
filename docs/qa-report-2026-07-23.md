## Findings (all minor)

1. **Asymmetric women-only lists.** The filtering uses two hardcoded lists that can drift: `DesignerApp` hides garment keys `{dress, skirt}` for men, but `Marketplace` only hides category slug `['dresses']` — **skirt is missing from the marketplace list.** No visible bug today (no "skirts" category exists), but if a tailor category for skirts is ever added, men would see it in the marketplace while the design studio hides it. Worth unifying.
2. **Section split is client-side only.** Gender lists are filtered server-side, but an individual dress product page (`/product/:id`) and the API remain reachable from the men's section — the garment/category hiding is UX guidance, not enforcement. Likely acceptable, flagging for awareness.
3. **Moving-marquee click target.** The hero gallery auto-slides continuously, so clicking a specific image is a moving target (42px/s — slow enough that real clicks land, and drag-detection has a 6px threshold, so it's fine functionally). Minor usability note for motor-precision; reduced-motion users get a static gallery.
